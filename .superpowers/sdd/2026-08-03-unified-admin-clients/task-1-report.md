## Requirement mapping

- `POST /api/v1/profiles/{profile_id}/plan` is a strict, bodyless profile view
  over the canonical planner. It uses the repository head and returns the same
  serialized plan bytes and digest as `POST /api/v1/reconciliations/plan` for
  the corresponding canonical request.
- `POST /api/v1/reconciliations` retains the canonical apply route, accepts a
  strict exact plan digest, returns bounded `409` for stale/unknown digests, and
  records `reconciliation.apply` audit events on success.
- `/api/v1/fleet` remains available and `/api/v1/nodes/status` is a typed alias
  over the same persisted fleet projection. Missing observations now render
  `healthy=null`, `stale=true`, and `probe_age_seconds=null`; old observations
  become stale after the bounded persisted-observation window. Neither route
  performs SSH or network probes.
- `GET /api/v1/endpoints/{alias}` resolves only the current, completed route
  publication owned by the live publication lease. It verifies the durable
  database activation marker against `/routes/activation.json`, the generation
  directory, `routes.json`, and all exact reconciliation/plan/generation/route
  digests. Missing aliases return bounded `404`; unavailable, pending, expired,
  or corrupt publication state fails closed with bounded `503`.
- `GET /api/v1/agents` is bounded to 500 registered nodes and bounded capability
  metadata. It exposes only state, protocol/capabilities, observation times,
  staleness, and certificate expiry; it excludes management addresses, CSR and
  certificate bodies, fingerprints, grant material, payloads, results, and
  private evidence.
- Existing job list/detail/log resources now have strict response models.
  Detail includes bounded typed child operations and current-attempt progress,
  without arbitrary payload/result objects. `POST /api/v1/jobs/{job_id}/resume`
  is strict and bodyless, enforces operator/admin RBAC, returns bounded
  `404`/`409`/`503`, and records `job.resume`. The legacy generic enqueue route
  remains for compatibility but is excluded from the admin schema and generated
  clients.
- Existing enrollment/grant/approve/reject/revoke routes remain intact. New
  mutation routes use the existing bearer, CSRF, request-ID, and audit machinery.
- The tracked admin OpenAPI document contains authenticated `/api/v1/*`
  operations, excludes `/agent/v1/*` and public health endpoints, assigns a
  stable explicit unique operation ID to every included operation, declares
  bearer authentication, prunes unused certificate-related components, and
  uses strict `additionalProperties=false` schemas for the new routine resource
  contracts.
- Python is generated by upstream `openapi-python-client==0.26.2`; TypeScript
  schema types are generated by upstream `openapi-typescript==7.13.0` with
  `typescript==5.9.3`. Exact versions are lockfile-pinned. The TypeScript runtime
  dependency is exact `openapi-fetch==0.13.8`; the Python generated runtime uses
  exact `attrs==26.1.0` and `httpx==0.28.1`.
- `scripts/generate-control-clients` sets deterministic process inputs, uses the
  locked upstream generators, and applies only a deterministic whitespace/EOF
  normalization to their output. The drift test snapshots the tracked schema
  and both generated clients, runs the generator twice, and requires identical
  bytes after each run.
- Hosted CI installs both locked generator environments and runs the drift,
  schema-security, generated-Python compile/import, and TypeScript build gates.
- The control API receives the route-publication volume read-only in Compose.

## Self-review

- Publication reads are local durable-state reads only and require the exact
  currently activated generation; no controller, SSH, or alias probe was added.
- Agent and job projections are bounded at the query and schema boundaries and
  do not copy persistence payload/result/private-evidence fields.
- Error bodies are stable and bounded; unavailable dependencies fail closed.
- The generated client tree is intentionally excluded from repository Ruff
  linting because it is upstream output, but is independently drift-checked,
  whitespace-normalized, compiled, imported, and TypeScript-built.
- Existing unrelated admin resources retain their established schema shapes;
  the new routine-operation contracts and their generated models are strict.
- No custom client generator, merge, push, or destructive repository operation
  was used.
