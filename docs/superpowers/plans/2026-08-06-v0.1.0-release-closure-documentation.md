# v0.1.0 Release Closure Documentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give operators one executable, fail-closed path for closing every remaining `v0.1.0` release gate without overstating unimplemented authority or physical-evidence tooling.

**Architecture:** A canonical release checklist owns ordering and status, while dedicated authority and physical-acceptance runbooks own their security boundaries. Existing entry points link to those documents and retain detailed subsystem procedures without duplicating release order.

**Tech Stack:** Markdown operator runbooks, GitHub CLI, GitHub Actions OIDC, TUF, canonical JSON, Ed25519 physical evidence, repository verification scripts.

## Global Constraints

- The protected GitHub Actions tag workflow is the only official platform build and publication path.
- Do not create/delete package versions, create `v0.1.0`, enable release variables, or claim physical evidence during this documentation change.
- Do not invent an authority server, signing key, physical exporter, or command that the repository does not ship.
- No site-specific Spark name, address, serial, secret, or fleet-size assumption may enter the documents.
