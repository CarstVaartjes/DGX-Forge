# v0.1.0 Release Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the normal protected GitHub Actions release path capable of producing the first complete DGX-Forge `0.1.0` platform candidate for both Docker control-host architectures and the ARM64 DGX Spark agent, without treating locally uploaded packages as official release artifacts.

**Architecture:** The existing tag workflow remains the sole build and GHCR publication path. A native `ubuntu-24.04-arm` job builds the self-contained Spark agent plus deterministic supervisor/tooling payloads and transfers them as immutable workflow artifacts to the package-writing release job. That release job publishes all six OCI artifacts, binds their actual manifest/SBOM/provenance evidence into the reviewed canonical input, and hands the resulting manifest to the already-isolated OIDC authority job. The final tag remains blocked until the delegated authority service and physical gates are ready.

**Tech Stack:** GitHub Actions, Docker Buildx, ORAS 1.3.2, Python 3.12/uv, PyInstaller, canonical JSON, OCI 1.1 artifacts, TUF delegation.
